# 燕园争锋使用与开发指南

## 1. 启动和停止

双击 `D:\PKUards\start.cmd`，或在 PowerShell 7 中进入项目运行 `npm start`，打开 `http://localhost:4173/PKUards/`。服务只监听本机。停止时在启动窗口按 `Ctrl+C`。

端口占用时运行 `npm start -- --port 4174`，随后访问相应端口。一键脚本固定使用 4173，换端口时使用命令启动。不要直接双击 `web/index.html`，浏览器对本地文件的模块加载有额外限制。

无需安装代码包。运行环境是已有 Node.js 22+ 与现代桌面浏览器。

## 2. 先玩一局

1. 大厅点击“初来燕园？先学一手”，按顺序完成部署、推进、攻击。教学使用独立练习状态，不覆盖正式对局。
2. “开始对战”选择四套预组之一，可选择对手阵营或随机对手。
3. 点击需要替换的起手牌，再确认。先手 4 张、后手 5 张，换牌仅一次，双方回合开始都抽牌。
4. 点击手牌，再点己方后场高亮空位。带指定登场效果的单位需要在选定卡位后，再点击高亮目标。
5. 点击己方场上单位，再点前线高亮空位推进，或点击高亮敌方单位/基地攻击。
6. 不需要指定目标的事件会在点击时直接使用；需要目标的事件点击后选择高亮目标。
7. 结束回合，将行动权交给 AI。进度每步自动保存，刷新会恢复未完成对局。
8. 卡牌右上角 `i` 打开完整规则与文案，`Esc` 或“取消选择”撤销当前选择。拖拽只作辅助，全部操作均可点击完成。

大厅导航可以暂时离开对局；返回“对战”继续。离开战场或打开详情时，AI 暂停思考；返回后继续。切到后台会完成正在结算的动作，再暂停后续 AI。正常页面跳转会保存已选定的当前行动，回到前台或返回页面后继续，不重复扣费。开始新对局会覆盖进行中的对局，界面会显示提醒。

## 3. 规则细节

### 拖动与出牌展示

按住手牌拖到己方后场空位部署；按住可行动单位拖到前线推进，或拖到敌方单位/基地攻击。事件拖向其合法目标，没有指定目标的事件拖入战场即可使用。卡牌随指针移动，箭头与边框显示落点是否合法，松手后结算。拖到无效位置、移出战场或按 Esc 取消均不扣费。鼠标支持点击和拖动；触屏采用点选卡牌再点目标，滑动用于浏览手牌与页面。

带指定登场技能的单位有两种拖法：先拖到后场卡位、再点击技能目标；直接拖向合法目标则自动选择可用后场（优先卡位 1，再选择其余合法位置）。如已无合法空位或无精力，拖动不会开始。

v1.2.1 使用克制的桌面反馈，没有全屏遮罩或卡牌飞行。自己出牌不再弹出展示卡；对手使用固定在手记区上方的 140px 小卡，停留 0.65 秒后，用细线指向目标，再显示短促的小数字。对手出牌总计约 1.09 秒，己方出牌/攻击约 0.4 秒，推进约 0.3 秒。期间暂停下一步操作和 AI，防止动作重叠。点击“跳过”或按空格/Esc 会完成当前动作，不会重复扣费。

右侧“同窗刚刚出牌”保留最近卡牌和最近六次出牌回看，作为中央动画后的速查记录。点击卡牌或卡名打开详情。只展示已经打出的牌，不展示对手手牌。

基地士气初始为 20，治疗最多恢复到 20。基地降至零即失败，同一个动作及其离场触发全部结算后双方同时归零为平局。友军不存在误伤，除非事件明确写明影响双方。

后场为 5 个固定卡位，中央卡位属于基地，其余 4 个可部署单位。前线有 5 个卡位，只能由一方驻守。守护按固定相邻卡位生效，空位不会自动压缩：基地左右的守护单位能保护基地。前线单位无法自行退回后场。前线最后一个单位离场后立即释放归属。

精力每个己方回合增长 1、补满，最高 12；不跨回合累积。移动和攻击分别扣除卡面“行动”费用。0 行动费用也受每回合行动次数限制。普通单位登场回合准备，速攻可以立即行动。普通单位每回合移动或攻击一次；突击可先移动一次再攻击一次，不能先攻击再移动。

| 单位 | 攻击与反击 |
| --- | --- |
| 近战 | 后场只能攻击敌方前线，己方前线可攻击敌方后场与基地；正常互伤 |
| 突击 | 射程同近战，可以先移动再攻击 |
| 炮击 | 可攻击任意敌方位置，绕过守护，主动攻击不受反击；被攻击时正常反击 |
| 拦截 | 任意射程，正常互伤；阻止敌方轰炸攻击本排其他目标 |
| 轰炸 | 任意射程并绕过守护，主动攻击仅拦截能反击；自己被攻击时不反击 |

隐蔽阻止单位选其为攻击目标，首次移动或攻击后解除；事件和指定登场效果不受守护、隐蔽、宣讲拦截限制。所有类型单位都可以推进前线，但远程单位通常留在后场更稳妥。

单位伤害同时结算，随后同时移除生命不大于零的单位，再处理离场触发；同批后续伤害继续触发清理。强化生命值同时提升当前生命与上限，治疗不能超过上限。回合开始先恢复精力和单位行动，再抽牌并处理回合开始技能。

手牌最多 9 张，抽牌溢出部分直接进入弃牌。牌库耗尽后，每次抽牌分别造成 1、2、3……疲劳伤害。召唤衍生伙伴优先使用后场从左到右的空位，位置不足部分跳过；召唤伙伴同样需要准备，除非具有速攻。

## 4. 自由组牌

“我的套牌”可以复制预组修改，也可创建空白套牌。选择主阵营和可选副阵营，点击左侧卡牌加入，右侧 `−` 移除一张。

- 合法套牌恰好 39 张，基地自动配置，不占编辑器计数。
- 同名可组牌卡最多 2 张；副阵营卡合计最多 12 张；中立卡不计副阵营数量。
- 不允许加入第三个阵营，也不允许直接加入技能衍生伙伴。
- 修改主副阵营会保留已选牌并显示不合法原因，便于手动调整。
- 保存按钮只对合法且已命名的套牌启用；预组始终保留原版。

套牌列表中点击“分享”取得以 `PKU1.` 开头的分享码。在另一台设备的“我的套牌”点击“导入套牌”，粘贴后选择“导入并编辑”，再保存。分享码保留套牌名称、主副阵营和每张卡的数量，不包含当前对局、战绩或浏览器存档 ID。导入始终创建独立草稿，预组和已有套牌不受影响。复制失败时可以手动复制已选中的代码。

编辑草稿随名称、卡牌和阵营修改自动保存。可以保留未满 39 张或暂时跨阵营的草稿，之后再修正；正式保存和出战仍须满足完整规则。刷新会回到仍在编辑的草稿，离开编辑器后可从“我的套牌”的“继续编辑”返回。当前保存一份编辑草稿，替换有内容的草稿前会确认，正式保存成功后清理草稿。草稿和原有对局分别保留。

左侧可同时筛选阵营、费用、单位类型和关键词，并搜索卡名、效果或文案。右侧费用曲线显示各费用区间牌数，6 表示 6 费及以上。

## 5. 修改卡牌和规则参数

在 `web/data.js` 编辑 `CARDS` 数组。

| 字段 | 用法 |
| --- | --- |
| `id` | 稳定的卡牌标识；改名会使旧套牌和存档失效，请优先保留 |
| `name` / `text` / `flavor` | 卡名、规则文本、故事文案；修改技能后同步修改规则文本 |
| `faction` | `science`、`engineering`、`humanities`、`society`、`neutral` |
| `cost` | 部署或使用费用 |
| `opCost` / `attack` / `health` | 单位行动费、攻击、初始生命 |
| `unitType` | `infantry`、`tank`、`artillery`、`fighter`、`bomber` |
| `keywords` | `blitz` 速攻、`guard` 守护、`smoke` 隐蔽 |
| `onDeploy` / `onDeath` / `onTurnStart` | 登场、离场、己方回合开始效果数组 |
| `onDraw` / `onMove` / `onOrder` | 成功抽入手牌、推进、每回合首次使用事件后的效果数组 |
| `signature` | 卡面的专属能力名称，需与真实技能效果配套 |
| `effects` | 事件牌效果数组 |

例如把“数院新生”的 `health` 从 `3` 改为 `2`，会改变其基础生命。把一张单位的 `opCost` 从 `1` 改为 `0`，只改变费用，不解除行动次数限制。

效果支持 `draw`、`damage`、`heal`、`buff`、`summon`、`discount`、`ready`（重新行动）。指定目标可用 `enemy`、`enemyUnit`、`friendly`、`friendlyUnit`；自动目标可用 `self`、`selfHq`、`enemyHq`、`allFriendlyUnits`、`allEnemyUnits`、`allUnits`、`enemyFront`（敌方前线）、`adjacentFriendly`（同排相邻友方，含基地）。可使用 `conditionFrontline`、`sourceInFront`、`hqAtMost`、`filterType` 限定效果。同张牌的多个指定效果应使用同一种选取规则；一个动作只选择一个指定目标。

`RULES` 汇总套牌数量、重复上限、基地士气、精力上限及手牌上限。前后场固定 5 格、基地中央的位置属于首版棋盘布局，若调整须同时修改引擎、UI 和相关测试，不能只改常量。改变规则合同后请递增存档版本，避免将旧局按新规则继续。

## 6. 调整 AI 与自动对局

`web/ai.js` 的 `AI_CONFIG` 包含 `frontierValue`（占线估值）、`cardValue`（抽牌估值）、`maxActionsPerTurn`（异常停滞保护）。增大占线估值会让 AI 更积极推进，增大抽牌估值会让它偏向资源积累。界面设置中的快速/标准/从容改变动画等待时间，不改变难度。

`web/tactics.js` 会先尝试短获胜顺序，再回到常规估值。搜索最多 160 个动作节点和 6 步，不搜索下一回合，也不打出搜索中抽到的未知占位牌。规则预演只使用可见投影，抽牌数量、疲劳和公开触发按真实引擎结算。该检查有界，不能保证找到所有获胜路线。

即时估值与规则共用目标解析，包括敌方前线、来源自身、类型过滤与相邻目标；当前部署和推进技能按动作完成后的位置、手牌与空位计入。它仍是启发式策略，不把未触发的后续回合技能当作即时收益。

界面通过 `web/ai-client.js` 复用一个模块 Worker，入口为 `web/ai-worker.js`。它只接收 `getObservation` 的结果与合法动作，不接收完整对局。隐藏、离开或打开对话框时取消未完成请求；返回后重新计算。Worker 不可用、出错或 8 秒未响应时回到相同的同步策略，避免对局停滞。`npm run test:ai` 验证真实 Worker、界面并行、取消与回退。

```powershell
npm test
npm run simulate
node scripts/simulate.mjs --seed 20261028 --rounds 2
```

默认覆盖 4×4 阵营配对，每组交换先后手，共 32 局。`--seed` 指定整数随机种子；`--rounds 2` 将每组重复两轮，共 64 局，允许 1–100。输出完整场次、终局、轮次及动作数，便于复现。每步都会检查状态合法性。此脚本用于验证引擎和 AI 能完成对局，不能凭少量 AI 互战判断实战平衡。

## 7. 存档和隐私

`localStorage` 使用 `pkuards:v1:decks`、`match`、`stats`、`settings` 保存四类正式记录，`draft` 独立保存编辑草稿及是否返回编辑器。某一部分损坏不会清除其他有效部分。对局只保存在当前浏览器和当前站点来源；本机端口、GitHub Pages 域名、不同浏览器之间不自动同步。浏览器禁止存储时会显示提醒，仍可进行当次对局。

当前局会保存完整游戏状态，但 AI 决策前仅获得可见投影：自己的手牌、双方公开单位、士气、精力、弃牌及手牌/牌库数量，不接收对手手牌、双方牌库顺序或随机数状态。战绩通过局 ID 去重，刷新已结束的对局不会重复计数。终局已经保存而战绩尚未写入时，下次打开会补记一次；统计写入失败后也可重试。

保存失败时，当前页面仍可继续游玩和保留套牌。套牌未能写入存储时会明确提示“暂存于当前页面”，请在刷新前复制分享码备份。游戏更新前会重新保存四类记录，无法保存时不会刷新页面。

## 8. GitHub Pages 发布

目标公开仓库为 `duyaOmega/PKUards`，主分支 `main`。首次发布需可用的 GitHub CLI 登录与仓库管理权限；需要重新验证时在本机运行 `gh auth login -h github.com --web --git-protocol https`。无需把令牌写入项目。

1. `npm test` 通过后，将源码、文档和轻量素材提交到 Git。
2. 创建公开仓库并推送 `main`，不要覆盖其他项目或强制推送。
3. 仓库 Settings → Pages → Source 选择 **GitHub Actions**。
4. 在 Actions 运行 **Test and deploy PKUARDS**。工作流先执行测试，再上传且仅上传 `web/`，随后部署 Pages。
5. 等待工作流成功，再访问 `https://duyaomega.github.io/PKUards/`；核对首页、脚本、样式和图标返回成功。

之后每次向 `main` 推送会自动更新。所有网站引用均为相对路径，页面通过站内状态切换，不依赖服务器路径回退，适用于 `/PKUards/` 项目子路径。

## 9. 本版验收说明

当前版本有 72 项自动测试、32 场基线自动对局，以及独立的桌面、触摸与离线浏览器检查。夜间增量还运行了 320 场对局。具体执行证据见 `docs/overnight-progress.md`，历史版本见 `docs/conclusion.md`。截图和机器报告位于忽略的 `artifacts/`。

运行 `npm run test:browser` 会自动启动已有 Chrome、Chromium 或 Edge，使用独立临时配置，结束后关闭并删除配置。可传 `--browser <现有浏览器可执行文件路径>`，或设置 `BROWSER_PATH`。整套检查不需要安装第三方代码包。离线检查使用独立本地地址，关闭 HTTP 服务后验证缓存，并模拟可接受和不完整的新版本。

用户已明确授权使用现有 Edge 无头模式。本地服务运行后，可以在 PowerShell 7 启动专用测试浏览器，再执行测试：

```powershell
$qaProfile = Join-Path (Get-Location) 'artifacts\edge-profile'
Start-Process 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe' -WindowStyle Hidden -ArgumentList @('--headless=new','--disable-gpu','--no-first-run','--no-default-browser-check',"--user-data-dir=$qaProfile",'--remote-debugging-port=9223','--remote-debugging-address=127.0.0.1','about:blank')
node scripts/browser-qa.mjs --port 9223 --base http://localhost:4173/PKUards/ --close-browser
```

此测试会在专用配置中写入并清理本游戏的测试对局，请仅对独立测试浏览器执行，不要对日常使用的浏览器调试端口运行。它使用真实鼠标事件执行拖动，截图包含中央亮牌、锁定目标、伤害和离场，并检查 1280×720 下手牌可见。Edge 路径应按现有安装位置调整；调试端口与 `--port` 一致，网站地址可通过 `--base` 修改。无需安装浏览器或代码包。

## 10. 插画与动画调整

`web/assets/art/` 包含 20 幅内置 image_gen 生成的油画主题 WebP，完整提示词在 `docs/art-prompts.json`。卡牌的 `art` 字段选择主题；主题可由多张相关卡复用。原始 PNG 保留在生成目录，不入库，不由网页加载。网页不调用生图 API。

如需重新优化已经生成的素材，可准备包含 `id` 和本地 `source` 的 JSON 数组，然后执行 `python scripts/prepare_art.py --manifest <清单路径> --width 960 --quality 84`。该辅助脚本使用电脑已有 Pillow，只做尺寸与编码优化。`--width` 允许 320–1920，`--quality` 允许 1–100；默认素材最大单文件约 216 KiB。本项目不自动安装 Pillow。

`web/presentation.js` 的 `playbackStages` 控制各阶段时长（毫秒）；`web/cinema.css` 控制中央亮牌、指向线、数字和移动的表现。效果结算发生在 impact 阶段，并由幂等播放控制器保证只提交一次。不要通过单独延迟 DOM 或在动画中再次调用引擎实现视觉效果。首次游玩时，减少动态效果默认遵循系统偏好；已保存的设置优先。减少动态效果保留静态卡名和目标说明，缩短动作过程。

本次规则版本升级为 2，旧版尚未完成的对局会提示重新开始；套牌、战绩与设置继续使用原存储键，全部保留。

## 11. 离线打开和更新

首次联网打开游戏后，等设置中显示“离线已就绪”，即可在断网时用同一网址打开，也可关闭本地服务后访问曾用的同一端口。全部 20 幅插画和游戏逻辑都随缓存提供。换浏览器、换端口、清除站点数据或浏览器自动回收缓存后，需要重新联网准备；分享码可用于转移套牌。

发现新版本时设置按钮出现小圆点。打开设置点击“保存并更新”，会先保存对局、套牌、战绩、设置和编辑草稿，再切换到新版本；不会在回合中自动刷新。如果新版本缺少资源，旧缓存保持可用。更新只清理当前游戏路径下的旧缓存，不清理其他站点应用的数据。

开发时，修改游戏资源后须同步递增 `web/sw.js` 的缓存版本和入口模块版本，避免同一版本长期使用旧资源。测试启动器每次创建新配置和随机本地端口，防止旧离线缓存使开发检查误测旧代码。不要在日常浏览器的调试端口上运行清理测试存档的脚本。

## 12. 连续完整对局验收

`npm run soak -- --games 32` 使用正常思考节奏和完整动画，在真实浏览器中从换牌到结算连续游玩，依次覆盖四阵营配对和先后手。桌面鼠标、手机竖屏触摸与横屏触摸交替运行。玩家侧由公开信息 AI 选择动作，再通过原生输入执行；每一步对照序列化后的真实规则结果。

该检查耗时较长，不作为普通 CI 步骤。它还检查每局战绩恰好计入一次、刷新不重复计数、已完成 ID 列表最多 100 项，并定期在垃圾回收后记录页面 JS 堆、DOM 数量与所持有的决策 Worker 数量。进度与报告为 `artifacts/browser-soak.json`，失败时保存截图与规则状态。`--games` 允许 1–1000，可用 `--until <ISO 时间>` 指定停止时间，`--source <提交号>` 标记所测源码。

可单独运行 `npm run test:activity` 检查原生标签页可见性和返回流程；`--headed` 使用独立浏览器窗口，适合有桌面显示环境时观察。普通 `npm run test:browser` 已包含这组检查，CI 不需要额外显示服务。

连续会话工具的 `--quick` 使用游戏现有的 250ms 思考与减少动态设置，例如 `npm run soak -- --games 112 --quick`。默认仍为标准 650ms 与完整动态。报告包含实际设置，不能把快速会话称为标准节奏验收；每场仍通过原生键鼠/触摸输入完整游玩，并验证逐步结算和战绩。进度报告采用临时文件原子替换，外部中断不会把上一份完整检查点截断。
