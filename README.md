# PKUARDS · 燕园争锋

一场发生在未名湖畔的校园策略卡牌交锋。四大学科阵营、64 张原创卡牌，以前线争夺和精力管理为核心，包含完整人机对局、自由组牌和四章「燕园行记」。

**在线游玩**：[duyaomega.github.io/PKUards](https://duyaomega.github.io/PKUards/)

**源代码**：[duyaOmega/PKUards](https://github.com/duyaOmega/PKUards)

当前发布结果见本文末尾的发布记录。

## 本地开始

电脑已有 Node.js 22 或更高版本时，双击项目根目录的 `start.cmd`，或在 PowerShell 运行：

```powershell
cd D:\PKUards
npm start
```

打开 <http://localhost:4173/PKUards/>。无需执行 `npm install`，所有游戏逻辑与插画均随项目提供，不加载 CDN、外部字体或远程 AI 服务。先点击“初来燕园？先学一手”完成三步互动教学，再选择预组出战。

手机浏览器支持竖屏游玩：左右滑动手牌，点选卡牌后再点高亮空位部署；点选场上单位，再点前线空位或攻击目标。底部保留行动提示、取消选择与结束回合。点卡牌右上角的 `i` 查看完整效果。触屏滑动用于浏览手牌和页面，鼠标仍可拖拽出牌。

## 已实现

- 64 张全部解锁的原创可组牌卡：12 个共享单位、4 个通用指令；四学科各 3 个专属单位、9 个指令。另有 4 种只由技能召唤的衍生伙伴。
- 理学探索、工学智造、人文思辨、社科纵横四套合法预组，每套 39 张抽取牌与 1 座基地。
- 起手换牌、逐回合精力、共享前线、五种单位、速攻/守护/隐蔽、反击与拦截、疲劳及平局。
- 后手额外拥有整局一次的「补给」：本回合临时获得 2 点精力，可超出常规上限；剩余临时精力回合结束时清除，未领取可留待以后回合。不占手牌、不触发指令联动。
- 不读取对手隐藏手牌和牌库顺序的本地策略 AI。
- 检查短获胜顺序的战术 AI，能安排连续攻击、重新行动与移除守护，避开可确定的当场自毁；策略计算使用可取消的本地 Worker。
- 卡牌搜索和多条件筛选、主副阵营组牌、费用曲线、套牌合法性检查。
- 当前对局、套牌、设置和战绩独立保存，支持刷新续局与部分损坏恢复。
- 套牌分享码，可在不同设备和浏览器之间手动转移套牌，或分享给同窗。
- 编辑草稿自动保存，支持刷新续写、返回编辑，并随游戏更新保留。
- 「燕园行记」四章单人挑战：西门、未名湖、图书馆、百讲；逐章解锁、收集地标印章，重访补星并保留最佳成绩。
- 首次缓存就绪后可断网打开；新版等待玩家在设置中选择“保存并更新”。
- 复古纸卡、木质战场、41 幅本地插画；12 个共享单位全部使用独立木刻角色图，突出脸部、动作和道具。支持简短目标动画、减少动态效果、点击及指针拖拽。
- 纯静态 GitHub Pages 部署，推送 `main` 后先测试再发布。

## 检查与调参

```powershell
npm test
npm run simulate
node scripts/balance.mjs --policy adaptive --rounds 20 --seed 160607 --out artifacts/balance.json
npm run test:browser
npm start -- --port 4174
```

`npm test` 包含 78 项检查，覆盖规则、组牌、草稿与存档恢复、套牌分享、战术顺序、章节目标及界面流程，含 32 场基线自动对局和 16 场章节/套牌组合对局。

`npm run test:browser` 自动使用电脑已有的 Chrome、Chromium 或 Edge，以临时独立配置执行七组浏览器验收，覆盖真实鼠标、触摸、键盘、屏幕尺寸、分享导入、离线更新、前后台切换、AI 响应及完整章节流程。可用 `npm run test:journey` 单独检查行记。不会操作日常浏览器，也不安装代码包或浏览器。可通过 `BROWSER_PATH` 或 `--browser <路径>` 指定现有浏览器；截图和机器报告保存在忽略的 `artifacts/`。

具体玩法、修改卡牌数值、调整 AI、恢复存档和部署步骤见 [docs/guide.md](docs/guide.md)。本次执行证据与验证范围见 [docs/conclusion.md](docs/conclusion.md)。

## 代码结构

| 位置 | 内容 |
| --- | --- |
| `web/data.js` | 卡牌、阵营、套牌、关键词及规则常量 |
| `web/engine.js` | 规则与状态转换，不依赖界面 |
| `web/ai.js` | 仅使用可见信息的动作评估 |
| `web/tactics.js` | 有界获胜顺序预演，不使用未知抽牌 |
| `web/deck-code.js` | 套牌分享码与导入规则校验 |
| `web/storage.js` | 分类存档与容错 |
| `web/offline.js`、`web/sw.js` | 完整离线缓存与玩家主动接受的更新 |
| `web/app.js`、`web/style.css` | 游戏界面、交互与响应布局 |
| `web/art.js`、`web/assets/art/` | 41 幅插画的加载与轻量 WebP 素材 |
| `web/journey.js`、`web/journey.css` | 四章行记、公开目标计数、最佳成绩与章节界面 |
| `web/presentation.js`、`web/cinema.css` | 中央亮牌、目标指向、冲击数字和串行动画 |
| `scripts/`、`tests/` | 本地服务、自动对局与测试 |
| `.github/workflows/pages.yml` | 测试与 Pages 发布 |

### 1.3.3 · AI 计算与界面并行

AI 使用一个复用的本地 Worker，只接收可见局面和合法动作。离开、隐藏或打开设置会取消未完成的决策，旧回复不会执行。不可用或超时会回到同一策略，保持当次游玩。离线缓存包括 Worker 及依赖，断网后也能完成 AI 回合。62 项 Node 检查、五组浏览器验收和一场原生输入完整对局通过。
